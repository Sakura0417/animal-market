## 0. 先说结论（判断优先）

| # | 结论 | 依据 |
|---|---|---|
| **1** | **网格化的"骨架"已落地，但最关键的"紧密排列"从未落地。** 现状是「网格上的稀疏均匀随机占格」，不是猪了个猪式的紧密排列 | `gridLayout()` = 60 格 Fisher-Yates 全洗牌取前 n，**本质是均匀随机**，无任何聚簇语义；实测 L8-L12 的 4 邻域均值 1.69 ≈ 纯随机理论值 1.67 |
| **2** | **遮挡玩法目前只发挥了不到一半的效力** —— 这是当前最大的玩法缺口，优先级高于 view 层收尾 | 实测初始被挡率仅 **32%**（L8-L12），即 **68% 的动物开局点一下就能走**；同数量改团簇布局后被挡率 **61%** |
| **3** | **"高关卡反向偏置制造链条"这句 PRD 要求从未实现** —— `smartDir()` 无 level 入参，全关卡同一策略，且 50% 概率**主动朝场外**（主动逃避遮挡） | `core/Board.ts:36` 签名 `smartDir(col, row, rng)`；`GameSession.generate` 调用处亦无 level |
| **4** | **出栏路径模型与紧密排列不兼容，且现状已经在带病运行** | 现状（均匀 30 只）已有 **21.7%** 的动物四面走廊全堵 → 回落弧线飞出；而弧线漂移是用户明确否决过的观感。紧密化后该比例升至 **37.5%** |
| **5** | 好消息：core 分层的红利仍在，上述三件事**全部可以在不改任何公开接口签名的前提下完成**，view 层 9 个文件里 6 个零改动 | 见 §5 各阶段"影响面" |

**一句话**：网格化不是"还没做"，是"做了一半且做错了半个"——**格子对了，排列没对**。补上紧密排列 + 换掉出栏路径模型，才是这套玩法的真正成型。

## 2. 核心设计要点提取

### 2.1 网格划分方式

| 项 | 规格 | 出处 |
|---|---|---|
| 盘面 | **6 列 × 10 行 = 60 格，等尺寸** | PRD §5.1 方案 A（v1.0 采用）；`Constants.GRID_COLS/ROWS` |
| 物理尺寸 | 牧场 286 × 478 设计像素 → **格距 47.67 × 47.8** | `GameView.buildLayout:232/235`（penW=286, penH≈478） |
| 占格 | 动物 / 岩石**各占一整格，同格不重叠** | PRD §5.1；`Grid.build` 首到者占格 |
| 精灵尺寸 | `sz = penW × 0.152 ≈ 43.5` → **占格率 91.2%**（相邻贴合） | `PenView:22` |
| 视觉 | 紧密排列、头顶箭头指示朝向；格线/格点**建议**低透明度绘制向玩家传达规则 | PRD §5.1 页面布局；分析文档 §5.3（**未实现**） |
| v1.1+ | 行列数由关卡配置逐级指定（密度升格为难度旋钮） | PRD §5.1 方案 C |

### 2.2 动物运动方向与边界约束（**这里有一处常见误解，必须澄清**）

> **PRD 里动物不是"自由移动"，是回合制的"静止待命 + 被点击后沿朝向一次性移动"。** 所谓"沿上/下/左/右四方向运动"指的是**朝向只有四向、且移动严格沿朝向轴**，不是每帧可操控的走位。

| 场景 | 规则 | 实现位置 |
|---|---|---|
| **朝向** | `Dir = up/down/left/right` 四向，生成时确定，静止期不变 | `core/Types.ts:9` |
| **被挡判定** | **相邻格遮挡**：朝向的下一格被动物或岩石占据 ⟺ 被挡。O(1) 占用图查表 | `Board.blockedBy` / `Grid.occupant` |
| **边界约束** | **边界格朝向场外 = 相邻格越界 = 视为空 = 未被挡、可走出** | `Grid.occupant` 越界返回 null |
| 被挡动物点击 | **仍可点击（不置灰）** → 沿朝向冲向遮挡者 → 接触红闪/粒子/震屏/**扣 1 心** → 过冲弹回原格；扣至 0 触发失败 | PRD §5.1；`GameView.takeAnimal` + `AnimalNodeC.bonk` |
| 未被挡动物点击 | 沿朝向走出牧场 → 沿土路跑到围栏口 → 入栏 | `PenView.roadWaypoints` + `GameView.moveTo` |
| 岩石 | 不可移动、不可选中，**但参与遮挡判定**；当前 `ENABLE_FARM_ROCKS=false` 全关为 0 | `LevelCfg:31` |
| 每次离场 | 全盘重算遮挡，新解锁动物播放 0.5s 弹跳 + 高亮 | `PenView.render(…, unlock)` |

### 2.3 数据结构

```
Animal（core/Types.ts）                    Grid（core/Grid.ts）
  uid      : int                             cells : (Animal|null)[60]   // row*COLS+col
  type     : AnimalDef                       static build(herd) → Grid
  dir      : Dir                             occupant(col,row) → Animal|null   // 越界 = null
  rare     : boolean                         static outOfBounds(col,row)
  obstacle : boolean                       ── 纯数据结构，不含规则，不耗随机流
  col / row: int   ◀ 唯一位置真相源
  get x()  = (col+0.5)*CELL_W               LevelConfig（core/Types.ts）
  get yu() = (row+0.5)*CELL_H                 level / herdN / typeCount / rocks / rareP / orderKinds
  （x/yu 是只读派生，view 过渡期兼容用）
```

**关卡 JSON schema（PRD §5.1 Phase A，尚未实现为 TS 类型）**

```json
{
  "cols": 6, "rows": 10,
  "rocks": [[2,3], [4,7]],
  "animals": [ { "col": 0, "row": 1, "dir": "up", "type": "pig", "rare": false } ]
}
```

### 2.4 接口清单（`core/Board.ts` + `core/Grid.ts`）

| 接口 | 签名 | 语义 | 耗随机流 |
|---|---|---|---|
| `Grid.build` | `(herd) → Grid` | 建占用快照（密集查询前建一次复用） | 否 |
| `Grid.occupant` | `(col,row) → Animal\|null` | O(1) 占格查询，越界=null | 否 |
| `Grid.outOfBounds` | `(col,row) → boolean` | 场外判定 | 否 |
| `blockerOf` | `(herd, b) → Animal\|null` | 朝向相邻格占用者（内部自建 Grid） | 否 |
| `isBlocked` | `(herd, b) → boolean` | 被挡判定 | 否 |
| `corridorOccupied` | `(herd, b, dir?) → boolean` | 沿 dir 扫到边界，任一格被占 = true（**出栏走廊体检**） | 否 |
| `pickExitDir` | `(herd, b) → Dir\|null` | 挑走廊干净的出栏方向：自身朝向 → 按到边界步数升序绕行 → 全堵返回 null | 否 |
| `unlockedSet` / `countUnlocked` | `(herd) → number[] / number` | 当前未被挡集合 | 否 |
| `unlockedCountOf` | `(herd, id) → number` | 某种类未被挡数量（订单偏向采样用） | 否 |
| `allLocked` | `(herd) → boolean` | 全场锁死 | 否 |
| `hasBlockCycle` | `(herd) → boolean` | 遮挡有向图成环（互锁，拒绝采样用） | 否 |
| `hasHeadOnPair` | `(herd) → boolean` | 2-环"对冲对"显式断言（A↔B 互朝） | 否 |
| `breakAllHeadOnPairs` | `(herd, rng)` | 定点翻向消除对冲对 | **是** |
| `smartDir` | `(col, row, rng) → Dir` | 50% 朝最近场外边 / 50% 随机 | **是** |
| `gridLayout` | `(n, rng) → {col,row}[]` | **60 格均匀随机取 n 个不重复格** | **是** |
| `reflow` | `(herd, rng)` | 洗牌：全场重新落位到随机不重复格（朝向不变） | **是** |
| `shuffle` / `randDir` | — | 基础工具 | **是** |

## 4. 技术难点（按风险从高到低）

### 4.1 难点一：紧密排列 —— 当前"网格"是稀疏的，遮挡机制形同虚设

**实测（本文新跑，n=30 / 300-400 局）**

| 布局 | 4 邻域均值 | 初始被挡率 | 初始解锁数 |
|---|---|---|---|
| **uniform（现状）** | 1.69（= 纯随机理论值 1.67） | **34%** | 19.8 / 30 |
| **cluster（团簇生长）** | 3.01 | **61%** | 11.6 / 30 |
| block（行优先满块，紧密度上限） | 3.27 | 68% | 9.8 / 30 |

GameSession 实跑交叉验证：L8/L12（30 只）被挡率 32.2%、初始解锁 20.3；L1（10 只）被挡率 10.1%、解锁 9.0。

**判读**：现状的 4 邻域均值与"纯随机撒点"的理论值几乎相等，说明**盘面根本没有聚簇结构**。结果是 L8 这种中后期关卡，30 只里 20 只开局即自由 —— 玩家几乎不需要规划路径，"挪车/猪了个猪"的空间解谜内核被稀释成了"点点点"。

**为什么之前没暴露**：难度调参（D8/T1）一直在用一审通过率做反馈，而通过率可以被订单复杂度单独拉回目标带 —— **数值被补偿了，但玩法质感没有**。这是典型的"指标达标、体验失真"。

### 4.2 难点二：出栏路径模型与紧密排列天然冲突（**最硬的技术难点**）

现状路径模型：动物**沿朝向直穿整个牧场**到路带。这在稀疏盘面勉强成立，紧密盘面必然频繁堵死。

**实测（四面走廊全堵率 = 回落弧线飞出的比例）**

| 布局 | 首选出口可用 | 需绕行 | **四面全堵 → 弧线兜底** |
|---|---|---|---|
| uniform n=24 | 33% | 53% | **13.7%** |
| uniform n=30（现状 L8-L12） | 27% | 52% | **21.7%** |
| cluster n=30（紧密化后） | 23% | 40% | **37.5%** |
| cluster n=34 | 20% | 39% | **40.6%** |

**关键推论**：**当前 L8-L12 已经有约 1/5 的动物是弧线飞出农场的** —— 用户 09-09 反馈的"漂移感"很可能不是偶发 bug，而是 20% 概率的系统性表现。紧密化后这个数字会翻到近 4 成，等于每 3 次出栏就有 1 次"漂移"。

**根因**：路径模型选错了。散点时代"沿朝向直穿"是唯一可行解；网格化后占用图已有，**沿空格寻路（BFS）才应该成为默认**——这也是猪了个猪/挪车类的通行做法，且网格化最大的红利之一就是让寻路变得可行。

### 4.3 难点三：难度曲线重标定（必然发生，成本已知）

改生成器 = 改变随机流消耗序列 ⇒ `baseline-snapshot.json` 必然失效。本项目的成熟做法（已用过 3 次）：
1. 先把新开关置为"等价旧行为"的值，跑 `sim:verify` 对拍旧快照，12/12 一致证明"新代码在关闭态与旧代码逐帧同构"；
2. 再置为新默认值，旧快照必然偏离 → 备份 + 删快照重建 + DEVLOG 说明。

紧密化后连锁解锁变长（移走一只解锁身后一串），难度会**结构性上升**，需重新扫参（优先调 `herdN`/密度，而不是改判定规则——判定规则是 PRD 定的）。

### 4.4 难点四：保底机制在紧密盘面下会退化

`generate()` 的 `do…while (un < 6 || hasBlockCycle)` 上限 40 次。紧密盘面下 `un` 天然走低（cluster n=34 时初始解锁约 12.5，还安全；但若密度再往上或叠加岩石，会频繁跌破 6），拒绝采样次数上升 → 生成耗时上升 + 布局质量靠重试运气。需要把"保底修复"从"整体重摇"升级为**确定性定向修复**（分析文档 §3.5 第 4 步本就要求：翻转若干被挡动物朝向指向空格），现状仍是整体重摇。

### 4.5 难点五：随机流纪律（新增参数不能插在既有调用中间）

新增任何 `rng()` 调用都会改变后续所有随机序列。若紧密化要新增"种子格选择""生长方向选择"等随机步，**只能在既有调用序列末尾追加，或整段替换**；否则快照对拍无法解释偏差来源。

### 4.6 难点六（低）：view 层三项收尾的技术含量不高但必须做

- **点格命中**：`onTap` 由 O(n) 最近圆匹配改为「本地坐标 → `floor(x/cellW), floor(y/cellH)` → 查占用」O(1)，零歧义；
- **±26° 倾斜**：网格对齐后必须去掉（现有"自然感"在紧密排列下就是"没对齐"）；
- **z 序**：按 `row * COLS + col` 行主序确定化，避免同一布局两次渲染遮挡关系不同。

## 5. 实现方案（分阶段，按依赖排序）

> 阶段 A、B 是**玩法成型的关键路径**；C 是收尾；D 是验收。建议顺序执行，每阶段独立验证。

### 阶段 A：生成器紧密化（core，约 1-1.5 天）

**目标**：让"紧密排列"从文档走进代码，同时保留难度旋钮。

| 步骤 | 改动 | 文件 |
|---|---|---|
| A1 | 新增 `clusterLayout(n, rng, tightness)` —— **团簇生长**：随机种子格 → 反复从已选格的 4 邻域随机取未选格加入；`tightness∈[0,1]` 控制"取邻域格 vs 取任意空格"的概率（0=现状均匀，1=纯团簇） | `core/Board.ts` 新增（**不删 `gridLayout`，并列保留**） |
