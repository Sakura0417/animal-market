## 一、格式（按优先级）

| 优先级 | 格式 | 说明 |
|---|---|---|
| ✅ 首选 | **GLB**（glTF 2.0 二进制） | 单文件、贴图内嵌、Cocos 3.8 原生支持，无依赖丢失风险 |
| ✅ 可收 | GLTF + 同名贴图（打包 zip 交付） | 保证 .bin/贴图相对路径完整 |
| ⚠️ 勉强 | FBX | 能收但轴/单位转换易出坑，需逐个人工校验 |
| ❌ 不收 | OBJ / STL | 无（完整）材质；OBJ 多文件易丢依赖 |

## 二、数量与命名

- 必交 7 个：`chicken / cow / duck / rabbit / sheep / pig`（6 物种，id 与 `core/AnimalSchema.ts` 一致）+ `rock`（岩石）。
- 可选 3 个预留物种：`alpaca / peacock / sika`（引擎零改动可扩）。
- 命名：全小写 `{id}.glb`，不加朝向后缀（朝向引擎侧 Y 轴旋转，不再多方向出模）。

## 三、硬验收线（不过线重导出）

| 项 | 标准 | 原因 |
|---|---|---|
| 体积 | 单个 ≤150KB，全套 ≤2MB | 微信主包 4MB 红线（还含代码/贴图/音频/字体） |
| 面数 | ≤3000 三角面/个 | 60 只同屏（L20+ 34 动物+4 岩石）低端机 drawcall/内存 |
| 贴图 | ≤512×512 PNG/JPEG，**内嵌**；纯顶点色/纯色材质更佳 | 卡通平涂 256 常够；贴图是体积大头 |
| 压缩 | **不要** Draco / meshopt / KTX2 | 微信小游戏端解码器兼容风险，体积靠低模+小贴图控制 |
| 材质 | 标准 PBR 或 unlit；**不用**扩展（KHR_materials_variants 等） | Cocos 导入器兼容面 |
| Alpha | 尽量不透明（opaque）；必须镂空（如羽毛边）用 alphaTest/cutout，避免 alphaBlend | 透明排序在小游戏端易出错 |
| 结构 | 单 Mesh 最好（≤3 子网格）；**静态**：无骨骼、无动画、无 LOD | 不做骨骼动画，纯朝向旋转 |
| 层级 | 无场景根变换：根节点不得带旋转/缩放/位移（归零烘焙进网格） | 避免 Cocos 导入后再校轴 |

## 四、坐标轴 / 原点 / 朝向 / 单位

| 项 | 标准 |
|---|---|
| 上下轴 | **Y-up**，右手系（glTF 标准，导出工具默认即是） |
| 朝向 | **统一面朝 +Z**（7 个必须一致；引擎内按朝向表绕 Y 轴旋转换向，个别模型反了我在代码加常量修正，但一致性能省这道工序） |
| 原点 | **脚底接触面中心** = (0,0,0)；模型在 X/Z 居中，整体在 Y≥0 上方 |
| 单位 | 米制（glTF 默认 1 unit = 1m） |
| 归一化 | 每个模型**高度归一到 1.0（±20%）**；物种体型差异（鸡<牛）由引擎按 schema 缩放，不要靠模型绝对大小表达 |

## 五、交付与验收流程

1. 模型放工作区任意目录，告诉我路径（逐个发也行）。
2. 我跑验收脚本：体积/面数/轴向/朝向逐项检查，报告过线情况。
3. 过线 → 导入 `assets/resources/art/models/{id}.glb` + 接线 `AnimalArt`/`AnimalNode`（VIEW_MODE 双模开关，2D 可回退）；不过线 → 退回重导出或引擎侧降级（缩贴图/减面）。
