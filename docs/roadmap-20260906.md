## 二、任务清单（优先级从高到低）

### T1 · 难度重建调参（对应 P4）⭐ 当前第一优先

- **目标**：L1-2 一审 ≥95% 保过；L3-5 一审 ≥85% 爬升；L6-12 一审 55-75%；恢复后全程 ≥95%；程序性卡死 0。
- **主要工作**：仅改 `core/LevelCfg.ts`（herdN/rocks/typeCount/rareP 逐级微调）；每轮跑 `npm run sim` 400 局曲线，必要时单关 1600 局深测；**改动扰动随机流 → 删 `baseline-snapshot.json` 重建 + DEVLOG 说明**。
- **依赖**：无前置；是 T4 的硬前置。
- **验收标准**：曲线五项指标全达标；新快照 12/12；boundary_check T1-T4 全绿；DEVLOG 记录新旧曲线对比。

### T2 · P5 三小项：C3 星级 / C4 黯淡特效 / C5 复活上限

- **目标**：补齐 PRD 2.0 明文的三个体验项。
- **主要工作**：① C5 在 core 加 `reviveLeft`（Constants 增复活上限常量，默认 2），GameView 复活入口判断，耗尽走 restart；② C3 `Panels.win` 增剩余生命星级显示；③ C4 生命耗尽时 herd 全体表情黯淡 0.5s 后再弹失败面板（AnimalNode/FxService）。
- **依赖**：互不依赖，可一批做完；须在 T4/T5 之前。
- **验收标准**：win 面板星级与剩余生命一致；第 3 次复活被拒且面板给出重开选项；黯淡动画肉眼可见；C5 改动不进随机流 → `sim:verify` 快照仍 12/12（不扰动是验收线）。

### T3 · D2 接触距离落地（小改动）

- **目标**：碰撞接触动画从不可见的 4.2px 改为默认 21px。
- **主要工作**：GameView 碰撞分支接触点/时长参数提取为 Constants 常量。
- **依赖**：无；T5 之前完成。
- **验收标准**：预览实测碰撞动画肉眼可辨、不破坏弹回节奏；不扰动随机流。

### T4 · A3 逐关人工验收（12 关）

- **目标**：每关真实可通关、体感难度符合曲线、无交互/视觉 bug。
- **主要工作**：编辑器预览 :7456 逐关真人通关并记录；发现的 bug 回灌 T1-T3 修复后复验。
- **依赖**：T1、T2、T3 完成。
- **验收标准**：12 关全部人工通关；bug 清单清零；DEVLOG 逐关记录。

### T5 · A5 特效对拍

- **目标**：粒子/飘字/震屏/心碎/彩带/星级与原型逐项对齐。
- **依赖**：T2（含新增 C4 特效）、T3。
- **验收标准**：逐特效 checklist 比对通过，差异项要么修要么明确接受。

### T6 · A4 微信构建 + 真机

- **目标**：微信开发者工具构建通过、真机可玩、包体合规。
- **依赖**：T4、T5。
- **验收标准**：AppID 构建成功；真机 12 关可进；主包 ≤4M；中端机帧率实测记录（目标 ≥50fps）。

### T7 · A7 真实广告接入

- **目标**：Mock 换 wx 激励视频（8 点位）。
- **依赖**：T6（需真实 AppID / 广告位 ID）。
- **验收标准**：真机 8 点位拉起真实广告、频控与 Mock 行为一致、无回调泄漏。

### T8 · D7 埋点最小集（上线前决策项）

- **目标**：给出最小埋点清单（关卡开始/失败原因/广告点位点击/通关/复活）或明确 v1.0 不做。
- **依赖**：无，但必须在 A4 前拍板。
- **验收标准**：决策落盘 DEVLOG；若做，埋点走 services 层不污染 core。

### 后置线（v1.0 上线后，已由 PRD 标注确认）

网格化 P1-P3（占用图/相邻遮挡/约束生成器/洗牌重排）→ 关卡 JSON schema → 编辑器 Phase A → D5/D6/D8 → hub 模块（首页/图鉴/签到）→ 性能红线专项。

## 三、当前最应聚焦的工作重点

**T1（难度调参）**。理由（第一性原理）：
1. **难度曲线是本作最贵资产**——PRD 2.0 的商业模型（前 2 关建立"我能赢"、第 3 关制造卡关峰转化广告）完全建立在曲线上，L3 一审 79.5% 意味着卡关峰提前且过陡。
2. **A3 会在过难关时卡住**——不先调参，逐关验收必然返工。
3. **成本最低**：只动 `LevelCfg.ts` 单文件，配合曲线扫描约半小时一轮，且新基线数据已在手。

## 四、与 AI 的协作方式建议

| 任务 | 分工 |
|---|---|
| T1 | AI 改 LevelCfg + 跑曲线 → 你只看对比数据拍板（每轮一个决策点：接受/继续调） |
| T2 | core 部分（C5）AI 直接改；view 部分（C3/C4）AI 出 diff → 你确认后 AI 落盘 |
| T3/T5 | AI 出方案，你预览实测 |
| T4 | **必须你亲手玩**，AI 负责修复记录到的问题 |
| T6/T7 | 你提供 AppID/广告位，AI 出构建步骤 |
